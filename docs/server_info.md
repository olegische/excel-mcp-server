# Анализ реализации MCP-сервера для Excel

## Обзор архитектуры

Сервер построен на базе библиотеки `mcp.server.fastmcp`, которая предоставляет высокоуровневый каркас для создания MCP-серверов. Это позволяет абстрагироваться от деталей реализации протокола и сосредоточиться на бизнес-логике.

Основная логика сосредоточена в файле `src/excel_mcp/server.py`.

## Ключевые компоненты

### 1. Ядро сервера (`FastMCP`)

Объект `mcp = FastMCP(...)` является центральной точкой приложения. Он инкапсулирует всю логику, связанную с обработкой MCP-сообщений. При его инициализации задаются метаданные сервера, включая имя, версию, зависимости и, что наиболее важно, переменные окружения.

### 2. Определение инструментов

Инструменты, предоставляемые сервером, определяются как обычные функции Python, декорированные `@mcp.tool()`. Фреймворк `FastMCP` автоматически обрабатывает эти функции, создавая для них соответствующие MCP-обертки. Это упрощает добавление новой функциональности.

Каждая функция-инструмент, как правило, выполняет следующие действия:
1.  Принимает примитивные типы данных в качестве аргументов.
2.  Преобразует относительный путь к файлу в абсолютный с помощью хелпера `get_excel_path`.
3.  Вызывает соответствующую функцию с "бизнес-логикой" из других модулей (`calculations.py`, `data.py` и т.д.).
4.  Обрабатывает исключения и возвращает строковое представление результата.

Такое разделение на "слой протокола" и "слой логики" является хорошей практикой.

## Запуск и транспортные механизмы

Сервер поддерживает два режима работы, которые определяются при запуске из командной строки (`src/excel_mcp/__main__.py`):

1.  **SSE (Server-Sent Events)**:
    *   Запускается командой `python -m excel_mcp sse`.
    *   Использует асинхронный веб-сервер для обмена данными по HTTP.
    *   Предназначен для сетевого взаимодействия.

2.  **STDIO (Standard I/O)**:
    *   Запускается командой `python -m excel_mcp stdio`.
    *   Обменивается данными через стандартные потоки ввода-вывода.
    *   Предназначен для локального взаимодействия с другими процессами.

## Конфигурация

Основной параметр конфигурации — это путь к директории с Excel-файлами. Его поведение зависит от режима запуска:

*   **В режиме SSE**: Путь определяется переменной окружения `EXCEL_FILES_PATH`. Если она не задана, используется значение по умолчанию `./excel_files`. Сервер работает в рамках этой директории, и в инструментах достаточно передавать только имя файла.
*   **В режиме STDIO**: Переменная окружения не используется. Во все инструменты необходимо передавать **абсолютный путь** к файлу.

Это обеспечивает гибкость: строгую "песочницу" для сетевого режима и свободу действий для локального.

## Работа с файлами

Сервер не работает с одним файлом в течение всего своего жизненного цикла. Каждый вызов инструмента является атомарной операцией, которая работает с файлом, указанным в параметре `filepath`. Состояние между вызовами не сохраняется на уровне сервера (кроме как в самих Excel-файлах).

## Развертывание в Docker

Сервер полностью готов к контейнеризации. Для этого необходимо:

1.  Создать `Dockerfile` на основе официального образа Python.
2.  Установить зависимости, перечисленные в `pyproject.toml`.
3.  Скопировать исходный код (`src`).
4.  Задать переменную окружения `ENV EXCEL_FILES_PATH` (например, `/data`).
5.  Использовать `VOLUME` для этой директории, чтобы монтировать данные с хост-машины.
6.  Открыть (EXPOSE) порт, используемый SSE-сервером.
7.  В качестве `CMD` указать команду для запуска сервера в режиме `sse`.

Такой подход позволяет легко развертывать и масштабировать сервис.
